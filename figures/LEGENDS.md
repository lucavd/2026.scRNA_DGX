# Figure Legends

**Figure 1.** Per-step speedup of the single-GPU pipeline (rapids-singlecell on one NVIDIA H100 80 GB) relative to the CPU pipeline (Scanpy on 100 cores, dual Xeon 8480C). Each cell shows the ratio of mean CPU wall time to mean GPU wall time across five independent repeats. Values greater than 1 indicate GPU is faster; values below 1 indicate CPU is faster. Columns correspond to dataset sizes (10k, 50k, 100k cells); rows correspond to individual pipeline steps. The 500k and 1.3M sizes are omitted because a single H100 runs out of VRAM at those scales.

**Figure 2.** Total pipeline wall time as a function of the number of GPUs (1, 2, 4, 8 NVIDIA H100 80 GB), with one line per dataset size. Error bars denote standard deviation across five repeats. Horizontal dotted lines indicate the corresponding CPU baseline (Scanpy, 100 cores). For 500k and 1.3M cells, only multi-GPU configurations (2, 4, 8) are shown because the single-GPU pipeline exceeds the 80 GB VRAM capacity. Note the logarithmic y-axis.

**Figure 3.** Concordance between CPU (Scanpy) and single-GPU (rapids-singlecell) pipeline outputs on 10,000 cells. Left panel: Adjusted Rand Index (ARI) and Normalized Mutual Information (NMI) comparing Leiden cluster assignments at three resolutions (0.5, 1.0, 1.5). Right panel: Jaccard index of the 2,000 highly variable genes (HVG), mean absolute Spearman correlation of PCA loadings across the first 10 principal components, and mean Jaccard overlap of k-nearest neighbor sets. All metrics are close to or equal to 1.0, indicating near-identical biological results from both backends.

**Figure 4.** Peak memory usage across dataset sizes. Left: peak CPU RAM for all pipeline configurations. Right: peak GPU VRAM (per-device maximum) for GPU configurations. The dashed red line marks the 80 GB per-device VRAM limit of the H100. For single-GPU runs, VRAM is approximately constant (~41 GB) due to RMM pool pre-allocation; for multi-GPU runs, aggregate VRAM scales with the number of workers. CPU RAM usage grows super-linearly with dataset size, reaching ~107 GB for 1.3M cells.

**Figure 5.** Step-level wall time decomposition for CPU (Scanpy, 100 cores) vs single-GPU (rapids-singlecell, 1 H100) at 10k, 50k, and 100k cells. Each stacked bar shows the mean time per pipeline step across five repeats. Total times are annotated above each bar. On CPU, DE testing and neighbor graph computation dominate; on GPU, all steps complete in seconds regardless of dataset size within this range.

**Figure 6.** Wall time decomposition for multi-GPU hybrid pipelines on 500k and 1.3M cells, compared to the CPU baseline. The hybrid pipeline executes QC, normalization, and HVG selection on CPU (blue), transfers the HVG-subset to GPU, then runs PCA and neighbor graph construction via Dask across multiple GPUs (pink), followed by Leiden clustering, UMAP, and DE testing on a single GPU (green). Total times are annotated above each bar. The near-identical wall times for 2, 4, and 8 GPUs demonstrate that only PCA and neighbor graph construction benefit from multi-GPU parallelism, while the CPU preprocessing phase and single-GPU steps dominate the total time.
